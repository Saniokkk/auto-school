# Деплой та SEO для філіалу Сквира

Цей файл описує, як правильно задеплоїти сайт після додавання другого філіалу
(`/skvyra/`), і що потрібно зробити поза кодом для SEO.

## Деплой

Збірка (`npm run build`) вже дає готову структуру — завантажуєте `dist/` як є,
нічого вручну реорганізовувати не потрібно:

```
dist/
├── index.html + ассети         ← головна (Тетіїв), відносні шляхи
├── skvyra.html                  ← легкий redirect на /skvyra/ (noindex)
└── skvyra/
    ├── index.html + ассети      ← філіал Сквира, абсолютні /skvyra/... шляхи
```

### Кроки

1. `npm run build` локально.
2. Залити **весь вміст `dist/`** у `www/` на хостингу, **зберігаючи підпапку
   `skvyra/`** як є (не розпаковувати її файли в корінь).
3. PHP-частина — окремо, вручну, не з `dist/` (Parcel її не збирає):
   - `send_mail.php`, `PHPMailer/` — залити/оновити на місце поточних
     (шлях до `config.php` не змінювався, він лишається там, де був).
   - `template_mail.html` — залити **з `src/`**, не з `dist/` (у `dist/` він
     під іншою назвою і з injected `<script>`, туди не підходить).
4. Після заливки перевірити вручну:
   - `/` — головна, топ-бар показує «Тетіїв».
   - `/skvyra/` — сторінка філіалу відкривається напряму.
   - `/skvyra` (без слеша) — має redirect'нути на `/skvyra/` (це робить сам
     сервер за замовчуванням для папки з `index.html`; якщо не редіректить —
     потрібен один рядок в `.htaccess`, звернутись за цим окремо).
   - `/skvyra.html` — має миттєво перекинути на `/skvyra/` (це та сама
     noindex-заглушка для сумісності з dev-режимом).
   - Відправити тестову заявку з **обох** сторінок — у листі має бути видно
     філіал у темі та тілі.
   - `sitemap.xml`/`robots.txt` — оновлені версії з корня репозиторію,
     теж залити.

CI (`gh-pages`) трогати не потрібно — він просто викликає `npm run build`,
працює як є.

## SEO — чому Тетіїв #1 і як підняти туди ж Сквиру

Важливо розділити два шари.

### 1. Технічна SEO-частина (на сайті) — вже зроблена

Унікальний `<title>`/description/H1/canonical для `/skvyra/`, Schema.org
`AutoSchool` зі своєю адресою та geo-координатами, сторінка в `sitemap.xml`,
внутрішні посилання (топ-бар + блок «Наші філії» у футері). Це необхідна,
але **не головна** умова топ-позицій.

### 2. Те, що реально рухає «Тетіїв» на 1 місце — скоріш за все не сайт, а:

- **Google Business Profile (картка на Google Картах)** для Тетіїв —
  відгуки, фото, підтверджена адреса/телефон. Для запитів типу
  «автошкола [місто]» Google здебільшого показує саме картку Maps
  (локальний пакет), а не органічну видачу сайту.
- Час — картка/сайт індексуються й набирають авторитет вже давно.
- Можливо, згадки в каталогах/соцмережах з тією ж адресою/телефоном
  (citations).

### Щоб Сквира повторила цей результат, самого коду не вистачить. Потрібно:

1. **Завести окрему Google Business Profile для філіалу Сквира** — з
   реальною адресою (тими ж координатами, що вказані на сайті), категорія
   «Автошкола». Це, скоріш за все, дасть більше ефекту, ніж усе інше разом.
2. Підтвердити її (Google надсилає код — поштою/відео).
3. Як з'явиться телефон Сквири — одразу додати його туди ж і на сайт
   (зараз у картці Google телефон обов'язковий для довіри).
4. Збирати відгуки на цій картці — свіжі й у кількості, це сильний фактор
   локального ранжування.
5. Додати `/skvyra/` у **Google Search Console** і явно запросити
   індексацію (не чекати, поки Google сам знайде) + завантажити туди
   оновлений `sitemap.xml`.
6. NAP-консистентність — адреса/телефон на сайті, у Google Business
   Profile і в будь-яких каталогах/соцмережах мають співпадати слово в
   слово.
7. Бажано додати хоча б один унікальний абзац тексту саме про Сквиру (не
   лише адресу) — зараз контент розділів (категорії, оплата, іспит)
   спільний із Тетіїв, це нормально для мультифіліальних сайтів, але пара
   унікальних речень підсилює релевантність саме цієї сторінки.
8. Реалістичні строки: навіть при всьому зробленому правильно — це тижні-
   місяці, а не миттєвий ефект, особливо поки немає відгуків та історії на
   картці філіалу.
